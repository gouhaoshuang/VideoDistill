# update-status - 更新项目文档

此命令自动扫描代码变更，同时更新 `docs/项目状态.md` 和 `docs/项目架构.md`。

## 功能说明

运行此命令后，AI 将：

1. **扫描代码变更** - 分析最近的 git 提交和文件修改
2. **识别已完成功能** - 根据代码变化判断完成的功能
3. **更新项目状态** - 更新任务进度、完成率
4. **同步项目架构** - 读取 src/ 目录实际文件，更新架构文档



## 工作流程

```
/update-status
      │
      ▼
1. 并行读取两个文档：
      ├─ docs/项目状态.md
      └─ docs/项目架构.md
      │
      ▼
2. 扫描代码库：
      ├─ 分析 git log 和 git diff
      └─ 读取 src/ 目录实际文件结构
      │
      ▼
3. 同步更新：
      │
      ├─ 【项目状态.md】
      │   ├─ ✅ 已完成任务移至"已完成"区
      │   ├─ 🔄 标记真实的"进行中"任务
      │   ├─ 📋 添加新发现的待办事项
      │   └─ 📊 更新概览统计
      │
      └─ 【项目架构.md】
          ├─ 📁 同步目录结构（新增/删除的文件）
          ├─ 🧩 更新核心模块（新增/修改的类和函数）
          ├─ 🔗 更新模块依赖关系
          └─ 📊 更新配置说明
      │
      ▼
4. 写入更新后的两个文档
```

## 架构同步

AI 会读取 `src/` 目录实际文件，重写 `docs/项目架构.md`：
- 目录结构（扫描所有文件和子目录）
- 核心模块（读取每个文件的类、函数、依赖）
- 数据流向（分析模块间的调用关系）
- 配置说明（读取 config.py）


## 更新规则

### 自动识别"已完成"

满足以下条件之一即视为完成：
- 功能代码已提交到 git
- 相关测试已通过
- 代码审查已完成


### 状态标签

| 标签 | 含义 |
|------|------|
| ✅ | 已完成 |
| 🔄 | 进行中 |
| 📋 | 待办 |
| 🐛 | 已知问题 |


## 注意事项

1. **自动日期**：已完成的任务会自动标注当天日期
2. **优先级**：新待办事项会根据影响程度标注优先级
3. **手动调整**：AI 更新后可手动微调内容
4. **git 同步**：建议在 git 提交后运行此命令
5. **架构同步**：AI 需要实际读取 src/ 下文件，而非仅依赖 git
