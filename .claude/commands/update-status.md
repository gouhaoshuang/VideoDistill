# /update-status - 更新项目文档

自动扫描代码变更，同步更新 `docs/项目状态.md`、`docs/项目架构.md` 和 `docs/项目环境.md`。

## 执行流程

```
1. 读取文档 → 2. 扫描代码 → 3. 分析变更 → 4. 同步更新 → 5. Git提交
```

## 扫描范围

| 目标 | 扫描内容 | 更新文档 |
|------|----------|----------|
| **代码变更** | `git log`, `git diff`, `git status` | 项目状态.md |
| **文件结构** | `src/` 目录实际文件 | 项目架构.md |
| **配置文件** | `requirements.txt`, `config.py` | 项目环境.md |

## 更新规则

### 项目状态.md
- 根据 git 提交自动标记已完成的任务
- 识别新增/修改的模块，更新"进行中"状态
- 更新完成率和统计信息

### 项目架构.md
- 同步 `src/` 目录结构（新增/删除的文件和目录）
- 更新核心模块说明（读取每个文件的类、函数）
- 更新模块依赖关系和数据流向

### 项目环境.md
- 同步 `requirements.txt` 依赖版本
- 提取代码中的环境变量（`os.environ` / `os.getenv`）
- 更新最后更新日期

## Git 提交

文档更新后，提交所有相关变更：

```bash
# 添加文档变更
git add docs/

# 添加命令文档本身（如修改）
git add .claude/commands/

# 提交
git commit -m "docs: 更新项目文档

- 同步代码变更到项目状态
- 更新架构文档目录结构
- 同步环境依赖版本"
```

> **注意**: 如果代码和文档同时修改，应一并提交所有相关文件，不只是文档。

## 状态标签

| 标签 | 含义 |
|------|------|
| ✅ | 已完成 |
| 🔄 | 进行中 |
| 📋 | 待办 |
| 🐛 | 已知问题 |
