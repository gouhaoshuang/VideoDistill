# 常用模式

## 骨架项目

实现新功能时：
1. 搜索经过实战检验的骨架项目
2. 使用并行 agent 评估选项：
   - 安全性评估
   - 可扩展性分析
   - 相关性评分
   - 实施规划
3. 以最佳匹配为克隆基础
4. 在验证过的结构中迭代

## 设计模式

### Repository 模式

将数据访问封装在一致的接口后面：
- 定义标准操作：findAll、findById、create、update、delete
- 具体实现处理存储细节（数据库、API、文件等）
- 业务逻辑依赖抽象接口，而非存储机制
- 方便更换数据源，简化测试时使用 mock

### API 响应格式

所有 API 响应使用统一的外壳格式：
- 包含成功/状态指示器
- 包含数据载荷（错误时可为 null）
- 包含错误消息字段（成功时可为 null）
- 包含分页响应的元数据（total、page、limit）
